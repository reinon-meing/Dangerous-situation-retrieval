# B70 测试脚本说明

> 2026-11-14 21:30 整理

---

## 为什么用脚本而不是直接敲命令

两个原因，都是踩坑换来的：

1. **终端粘贴容易被搞乱**——长命令被截断、混入上一行的字符，导致奇怪的报错
2. **心跳必须和程序同生共死**——每段脚本内部都用 `&` 启动了 `/api/fsm/enable` 心跳，并在结束时 `kill` 掉

**所有脚本的第一行都是发心跳**，这是它们能起作用的前提。

---

## 三个脚本的分工

```
test_arm.sh   →  「手臂能不能被指令驱动？」（不跑模型）
reset_arm.sh  →  「把手臂复位到零位」
run_policy.sh →  「跑训练的模型控制手臂」
```

**使用顺序：test_arm → reset_arm → run_policy**

---

## 1. `test_arm.sh` — 手臂动作自检

### 干什么

不启动模型，**直接手动发一个目标位姿**给 `/api/left_arm/joint_cmd`，比较发送前后的实际关节角。

### 为什么需要它

**这是区分"模型问题"和"硬件问题"最快的方法。**

不看这个就跑模型，一旦手臂不动，你会误以为是：
- 模型没训好
- 数据有问题
- 部署失败

实际可能只是**急停没旋出**或**心跳没发**。花 10 秒跑这个，能省下几小时的错误排查。

### 内容

```bash
ros2 topic pub -r 20 /api/fsm/enable ... &        # 心跳
sleep 1
读 /left_arm/joint_states  →  BEFORE
ros2 topic pub -r 20 /api/left_arm/joint_cmd ... &  # 发目标
sleep 5
读 /left_arm/joint_states  →  AFTER
```

### 怎么读结果

| BEFORE vs AFTER | 结论 |
|---|---|
| **明显变化，接近目标** | 链路 + 电机 + FSM 全部正常 |
| 几乎不变 | 电机没执行 → 查急停 / 碰撞检测 / 上电 |

### 实测记录

| 时间 | 结果 | 原因 |
|---|---|---|
| 20:45 | ✅ 动到目标 | 正常 |
| 21:04 | ❌ 不动 | 急停未旋出（当时未发现） |
| 21:26 | ✅ 恢复 | 旋出急停后 |

## 2. `reset_arm.sh` — 复位到零位

### 干什么

调用官方 `zero.py`，让双脚（双臂）运动到预设零位，并等待收敛。

### 为什么需要它

1. **每次跑模型前都要复位**——模型是在固定起始姿态的数据上训练出来的，起点不一致会得到错误动作
2. **它本身就是最好的"电机有没有使能"检测器**——内置收敛判断（容差 0.05 弧度，持续 0.5 秒）

### 内容

```bash
心跳 &
sleep 1
timeout 60 python examples/teleavatar_v2/zero.py
```

### 怎么读结果

| 输出 | 含义 |
|---|---|
| `Both arms converged! Shutting down...` | ✅ 复位成功，电机正常 |
| 一直刷 `not converged` | ❌ 电机不动（急停 / 未上电） |
| 刷 `Current position not set yet` | ❌ 收不到关节状态（容器 ROS 栈退化，要重启容器） |
| 60 秒超时 | ❌ 卡住 |

---

## 3. `run_policy.sh` — 跑模型

### 干什么

启动 `main.py`，让**训练好的模型**驱动手臂。

完整链路：

```
main.py 收视频（UDP 8890，VA-API 硬解）
   ↓ 图像 + 关节角 + prompt
server（B70 GPU 0，端口 8000）推理
   ↓ 16 维动作，30 步一块
main.py 翻译成 /api/left_arm/joint_cmd 等
   ↓
机器人执行
```

### 内容

```bash
心跳 &
sleep 1
python examples/teleavatar_v2/main.py \
  --remote-host 127.0.0.1 --remote-port 8000 \
  --video-decode va --prompt "pick sandbag"
```

### 参数要点

| 参数 | 值 | 注意 |
|---|---|---|
| `--prompt` | `pick sandbag` | **必须和训练的 `--task` 一字不差** |
| `--video-decode` | `va` | 硬解，容器用 renderD129 |
| `--enable-chassis` | **不加** | 16 维模型，加了报错 |
| `--rtc` | **不加** | 服务端没开 RTC |

### 成功日志

```
Connected to policy server
✓ All sensor data received!
Starting robot control loop...
First des_q command published -- the arm is now being driven
```

## 怎么把脚本部署到 B70

在 **Windows PowerShell** 里：

```powershell
scp E:\怀客松\b70_scripts\*.sh root@192.168.31.128:/root/
```

或者在 B70 上用 heredoc 直接写（见各脚本内容）。

## 怎么执行

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -s < /root/脚本名.sh
```

`bash -s` 从标准输入读脚本，避开粘贴问题，也带上了镜像的 ROS 环境。

## 怎么停止

`main.py` 运行时按 **Ctrl-C**；如果不管用：

```bash
docker exec openpi-xpu-client pkill -INT -f examples/teleavatar_v2/main.py
```

**严禁 `docker stop` / `kill -9`** —— 会跳过零速度指令。

---

## 执行纪律（血泪教训）

| 规则 | 原因 |
|---|---|
| **先 test_arm，再 run_policy** | 否则会把"执行链路问题"误判成"模型问题" |
| **每轮测试前重启 client 容器** | 跑久了 ROS 栈会退化（participant 耗尽、订阅丢失） |
| **每轮最多 3 条 exec** | 每条命令都创建一个 ROS 节点 |
| **跑模型前必须 reset_arm** | 起点姿态要和训练一致 |
| **手放急停上** | 模型行为不可预测 |
