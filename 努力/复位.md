# 复位（摆位）操作说明

> 2026-11-14 22:30
> 为什么需要"复位"：模型是**增量式关节控制**（`use_delta_joint_actions=True`），
> 输出的动作是相对当前关节角的增量。起点姿态不同 → 增量累加的基准不同 → 动作全歪。

---

| 关节 | zero | raised | 差值 |

| j1 | 0.405 | 0.269 | -0.14 |
| j2 | 1.162 | 1.359 | +0.20 |

## 二、什么时候用哪个

| 跑哪个模型 | 用哪个复位 | 原因 |
|---|---|---|
| `move_vaapi` 训的（v1/v2） | **`reset_arm.sh`**（zero.py） | 旧数据起点是零位 |
| **`move_raised` 训的（v3）** | **`pose_raised.sh`** | 新数据起点是抬高姿态 |

⚠️ **用错会导致模型看到"没见过的起点" → 输出离谱动作或干脆不动。**

## 三、复位命令

### 方式 A：摆到零位（官方 zero.py）

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -s < /root/reset_arm.sh
```

成功标志：`Both arms converged! Shutting down...`

### 方式 B：摆到抬高起点（新数据用）

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -s < /root/pose_raised.sh
```

成功标志：打印出实际关节角，且接近目标值（偏差 < 0.05 弧度）。

### 方式 C：手动发任意目标

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -c \
  'ros2 topic pub -r 20 /api/fsm/enable std_msgs/msg/Float32 "{data: 1.0}" >/dev/null 2>&1 &
   HB=$!; sleep 1
   ros2 topic pub -r 20 /api/left_arm/joint_cmd sensor_msgs/msg/JointState \
     "{position: [j1, j2, j3, j4, j5, j6, j7]}" >/dev/null 2>&1 &
   PUB=$!; sleep 6; kill $PUB $HB 2>/dev/null'
```

## 四、复位的三条铁律

### ① 必须带 FSM 心跳

所有复位命令都要先发心跳，否则手臂不执行：

```bash
ros2 topic pub -r 20 /api/fsm/enable std_msgs/msg/Float32 "{data: 1.0}" &
```

心跳断 1 秒 → 手臂自动暂停。

### ② 必须先确认急停已旋出

```bash
# 用手推一下手臂，应该掰不动
```

**急停没旋出 = 电机没电 = 任何复位都不会动。** 这是今晚最大的坑。

### ③ 复位后要验证到位

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -c \
  'timeout 2 ros2 topic echo --once /left_arm/joint_states --field position 2>/dev/null | grep -o "array.*"'
```

**实际值应该接近目标值（偏差 < 0.05 弧度）。**

## 五、录制时如何保证起点一致（下次改进）

你现有 56 条的起点 std：**0.126 ~ 0.230**（偏松，7–13° 波动）

| std | 判断 |
|---|---|
| < 0.05 | 好 |
| **0.13–0.23（现有）** | 一般，能训但不够稳 |
| > 0.3 | 差，要重录 |

**改进做法**：录制前先自动摆位，不靠手感。

```
① 队友跑 pose_raised.sh 自动摆到标准起点
② 只做 ±2° 内微调
③ 静止 1 秒
④ 按 X 开始录
```

这样能把 std 压到 0.05 以内。

## 六、已知问题：j7 贴限位

| 关节 | raised 起点 | 软限位 | 余量 |
|---|---|---|---|
| **j7** | **0.654** | **0.700** | **0.046** ⚠️ |
| j2 | 1.359 | 1.900 | 0.541 🟡 |

**j7 手腕几乎拧到底**，模型想再往外拧就被限位砍掉：

```
left_arm command clamped to joint limits: l_joint7 1.150->0.700
```

**这会导致手臂看起来"不动"**（命令被夹在 0.7）。

### 下一批录制改进

> 开录前把**手腕往回收一点**：j7 从 0.65 收到 **0.30–0.40**，留出双向余量。
> j2 也可以从 1.36 降到 1.20 左右。

## 七、速查表

```
是否需要复位？
  └─ 每次跑模型前：必须

用哪个？
  ├─ move_vaapi 模型 → reset_arm.sh（zero 位）
  └─ move_raised 模型 → pose_raised.sh（抬高位）

复位前检查？
  ├─ 急停旋出（手推手臂，掰不动）
  ├─ /fsm_state == 1
  └─ client 容器状态正常

复位后验证？
  └─ 实际关节角 vs 目标，偏差 < 0.05
```
