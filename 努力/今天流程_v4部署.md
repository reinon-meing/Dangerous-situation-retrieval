## 第 8 步：★ 手臂动作自检 ★（不启动模型）

```bash
cd /root/USB/deploy

client/run_client.sh exec bash -c '
ros2 topic pub -r 20 /api/fsm/enable std_msgs/msg/Float32 "{data: 1.0}" >/dev/null 2>&1 &
HB=$!; sleep 1

echo "--- FSM 状态（必须是 1）"
timeout 2 ros2 topic echo --once /fsm_state --field data

b=$(timeout 2 ros2 topic echo --once /left_arm/joint_states --field position 2>/dev/null | grep -o "array.*")
echo "BEFORE: $b"

ros2 topic pub -r 20 /api/left_arm/joint_cmd sensor_msgs/msg/JointState \
  "{position: [0.70, 1.60, -0.90, 1.10, 0.50, -0.40, 0.60]}" >/dev/null 2>&1 &
PUB=$!; sleep 5; kill $PUB 2>/dev/null

a=$(timeout 2 ros2 topic echo --once /left_arm/joint_states --field position 2>/dev/null | grep -o "array.*")
echo "AFTER : $a"
kill $HB 2>/dev/null
'
```

⚠️ 跑之前**手放急停**，手臂会转约 0.4 弧度（23°）。

| BEFORE vs AFTER | 结论 |
|---|---|
| 数字明显变化 | ✅ 进第 9 步 |
| 数字几乎相同 | ❌ 查急停 → fsm_state → 模式 → 碰撞检测 → 推一下手臂（掰不动=有电） |

## 第 9 步：摆位（⚠️ 用 pose_raised.sh，不是 zero.py）

```bash
docker exec -i openpi-xpu-client \
  /usr/local/bin/openpi-client-entrypoint.sh bash -s < /root/pose_raised.sh
```

**原因**：v4 数据是"抬高姿态"起手的，起点必须一致。用 `zero.py` 会让起点和训练数据差 0.49 弧度（28°），手臂不动或乱动。

### 判断树

```
手臂动吗？
 ├─ 不动 → 急停（推一下，掰不动=有力）→ fsm_state → 容器跑太久就重启容器
 └─ 动 → 方向对吗？
          ├─ 朝沙包伸 → ✅ 记录：能不能抓到 / 抓完抬高
          └─ 冲限位/乱动 → 模型问题：
               ① 换位置再试一次（检验过拟合）→ 还是乱
               ② 退 v3：mv /root/ckpt_out /root/ckpt_out_v4;
                        mv /root/ckpt_out_v3 /root/ckpt_out
                        然后重起 server（第 5 步），软链已经是 path-to-dataset
```

## 已知会咬人的点（今天这几条最可能）

| # | 坑 | 处理 |
|---|---|---|
| 1 | 急停没旋出 | 推一下手臂：掰不动 = 有电 |
| 2 | FSM 心跳没发 | 心跳必须和程序同一 shell |

| 5 | 用 zero.py 摆位 | 用 `pose_raised.sh` |
