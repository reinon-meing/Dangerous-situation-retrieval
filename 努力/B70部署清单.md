# B70 部署清单（Server + Client）

> 依据：U 盘 `deploy/server/openpi-xpu-env/README.md`、`deploy/client/README.md`、`deploy/client/run_client.sh`
> 目标配置：`pi05_teleavatar_v2_chassis`（19 维动作，含底盘）

---

## 部署全景

```
A100 训练 → JAX checkpoint（42 GB）
    ↓ ① 传到 B70
B70 → JAX checkpoint 落地
    ↓ ② 转成 PyTorch（CPU，需 32 GB 内存）
PyTorch checkpoint（/path/to/ckpt）
    ↓ ③ 建 assets 软链接
    ↓ ④ 起 server（127.0.0.1:8000，用 renderD128）
    ↓ ⑤ 起 client（zenoh 连机器人，用 renderD129 硬解视频）
机器人 ← API 指令
```

**关键点：训练产出的是 JAX checkpoint，B70 推理要 PyTorch checkpoint，中间必须转换。** 每个 checkpoint 只需转一次。

---

## 前置检查（第一次部署前做一次）

```bash
# 1. 内存：转换 checkpoint 需要约 32 GB
free -g

# 2. 两块卡的 render 节点确认
ls -l /dev/dri/renderD*
xpu-smi discovery | grep -E "Device ID|DRM"

# 3. 两个镜像都在
docker images | grep -E "openpi-xpu"

# 4. 确认没有别的 zenoh 服务在抢
systemctl is-active zenoh-bridge-ros2dds.service
ss -tln | grep -E ':7447\b'

# 5. 确认 8890 端口空闲（机器人要把视频推到这里）
ss -uln | grep -E ':8890\b'
```

## ① 把 checkpoint 从 A100 传到 B70

训练产物在 A100 平台：

```
/outputs/checkpoints/pi05_teleavatar_v2_chassis/v1-25e/<step>/
├── params/          ← 模型权重
├── assets/          ← 归一化统计、tokenizer 等
└── train_state/     ← 训练状态，部署不需要
```

**需要的是 `params/` 和 `assets/`，`train_state/` 可以不传（省 12.5 GB）。**

传输路径（两台机器互不可达时走 Windows 中转）：

```powershell
# 1. A100 → Windows
scp -r -i C:\Users\Reinon\ta-team3\team_key -P 20100 root@120.92.21.123:/outputs/checkpoints/pi05_teleavatar_v2_chassis/v1-25e/2000 "E:\怀客松\ckpt_2000"

# 2. Windows → B70
scp -r "E:\怀客松\ckpt_2000" root@192.168.31.128:/root/jax_ckpt/
```

> 42 GB 传输会很慢。**先在 B70 上试 B70 → A100 能否直连**，能直连就省一半时间。

## ② 转成 PyTorch checkpoint

在 B70 的 `deploy/server/openpi-xpu-env/` 目录下执行（`$OPENPI_DIR` 指向 **server 分支**的 openpi 代码）：

```bash
export OPENPI_DIR=/root/USB/deploy/server/openpi      # 或拷贝到本地后的路径
cd /root/USB/deploy/server/openpi-xpu-env

OPENPI_DIR=$OPENPI_DIR XPU=0 GPUS=none OUTPUT_DIR=/root/ckpt_out \
  DOCKER_RUN_EXTRA="-e JAX_PLATFORMS=cpu -v /root/jax_ckpt/2000:/jax:ro" \
  scripts/run.sh python examples/convert_jax_model_to_pytorch.py \
    --checkpoint-dir /jax \
    --config-name pi05_teleavatar_v2_chassis \
    --output-path /outputs/pi05_teleavatar_v2_chassis_pytorch \
    --precision bfloat16
```

⚠️ 注意：
- `--config-name` **必须**是训练时用的配置名 `pi05_teleavatar_v2_chassis`
- `XPU=0 GPUS=none` 是故意的——转换在 CPU 上做
- 转换结果在 `/root/ckpt_out/pi05_teleavatar_v2_chassis_pytorch`

## ③ 建 assets 软链接（容易漏）

转换脚本会把归一化统计拷到 `assets/<数据集目录名>/`，但**服务端按配置里固定的名字查找**：

| 服务用配置 | 软链接名 |
|---|---|
| `pi05_teleavatar_v2` / `_rtc` | `path-to-dataset` |
| **`pi05_teleavatar_v2_chassis`** | **`checkout_224_plus_no_scan_224`** |

```bash
cd /root/ckpt_out/pi05_teleavatar_v2_chassis_pytorch/assets
ls                              # 看到 move_vaapi（我们数据集的名字）
ln -s move_vaapi checkout_224_plus_no_scan_224
ls -l                           # 确认软链建好
```

**不建这个软链，服务端启动会找不到归一化统计而失败。**

## ④ 启动 server

```bash
export OPENPI_DIR=/root/USB/deploy/server/openpi
cd /root/USB/deploy/server/openpi-xpu-env

OPENPI_DIR=$OPENPI_DIR \
DOCKER_RUN_EXTRA="-p 8000:8000 -v /root/ckpt_out/pi05_teleavatar_v2_chassis_pytorch:/ckpt:ro" \
  scripts/run.sh python scripts/serve_policy.py --env TELEAVATAR --warmup \
  policy:checkpoint \
  --policy.config pi05_teleavatar_v2_chassis \
  --policy.dir /ckpt \
  --policy.pytorch-device xpu \
  --policy.pytorch-compile-mode default
```

要点：

| 项 | 值 | 说明 |
|---|---|---|
| 端口 | `8000` | client 要连这个 |
| `--warmup` | 开 | 先在监听前完成编译，避免第一个请求卡顿 |
| `--policy.config` | `pi05_teleavatar_v2_chassis` | 必须和训练配置一致 |
| RTC | **不开** | 我们没用 RTC 配置训练，所以服务端不加 `--rtc.*` |
| 用哪张卡 | `ZE_AFFINITY_MASK=0`（默认） | server 用 renderD128 |
| 显存峰值 | 约 7.3 GiB | |
| 加载时内存峰值 | 约 15.7 GiB | |
| 冷编译 | 65–100 s | 热缓存 22 s |

**成功标志**：日志出现监听 8000，`curl -s localhost:8000` 有响应。

## ⑤ 机器人侧设置（一次性的，很关键）

不改这些，机器人**不会执行策略指令**：

1. **切 API 模式**
   机器人的 remoteApp（或接显示器的 System Config 面板）：
   - Run mode → **API**（默认是 VR）
   - 启用左臂、右臂；**控制模式设为 joint**
   - 先点 **Save config**，再点 **Apply**
   - 重启机器人确认电机正常使能

2. **视频推流指向 B70**
   在推流 remote APP 里把目标 IP 设为 **B70 的 IP（192.168.31.128）**，UDP 端口 8890，启动推流。

3. **确保没有第二个控制源**
   其他子网的控制端不运行；B70 宿主机的 `zenoh-bridge-ros2dds.service` 必须停掉。

## ⑥ 启动 client

**必须先 `sudo -i` 切到 root**（client 要改显卡频率，普通用户会失败；而且 `sudo client/run_client.sh` 不会传递 `export` 的变量）。

```bash
sudo -i
cd /root/USB/deploy
export OPENPI_DIR=$(pwd)/client/openpi          # 必须绝对路径

# 1. 启动常驻容器（自动拉起 zenoh 桥）
RENDER=/dev/dri/renderD129 ZENOH_ENDPOINT=tcp/192.168.31.217:9000 \
  client/run_client.sh start

# 2. 检查状态：确认 bridge.log 正常，能看到 /left_arm/joint_states 等话题
client/run_client.sh status

# 3. 回零（每次都先跑这个，让机械臂到已知姿态）
client/run_client.sh exec python examples/teleavatar_v2/zero.py

# 4. 主程序（硬解视频 + 底盘）
client/run_client.sh exec python examples/teleavatar_v2/main.py \
  --remote-host 127.0.0.1 --remote-port 8000 \
  --video-decode va \
  --enable-chassis \
  --prompt "pick sandbag"
```

### 参数对应表（必须两端配套）

| 训练配置 | server `--policy.config` | client 参数 |
|---|---|---|
| **`pi05_teleavatar_v2_chassis`（我们）** | `pi05_teleavatar_v2_chassis` | **加 `--enable-chassis`** |
| `pi05_teleavatar_v2` | `pi05_teleavatar_v2` | 不加，输出 16 维 |
| 任何 RTC 配置 | `--rtc.enabled` | 才加 `--rtc` |

- **两端不一致，第一个动作就报错**
- 服务端没开 RTC，客户端**不要**加 `--rtc`
- `--prompt` 必须和训练的 `--task` 一致（我们用 `"pick sandbag"`）

### 为什么 client 用 renderD129

`run_client.sh` 注释写明：`renderD128` 是策略服务端用的卡，`renderD129` 是另一张。server 用 `ZE_AFFINITY_MASK=0`（renderD128），**所以 client 视频硬解要用 renderD129**。

## ⑦ 安全停机（必须遵守）

```bash
# 正确：Ctrl-C，或
client/run_client.sh exec pkill -INT -f examples/teleavatar_v2/main.py
client/run_client.sh stop
```

**严禁 `docker stop` / `kill` / `rm -f`** —— 会让进程被 SIGKILL，**底盘会继续移动约 1 秒**。

**SSH 断连不会停止程序**，机器人会继续运动。断网时**先拍现场急停**，重连后用 `pkill -INT` 停。

**开底盘前的强制检查**：

```bash
client/run_client.sh exec ros2 topic info -v /api/chassis/velocity
```

必须看到节点名为 `zenoh_bridge_ros2dds`、`Reliability: RELIABLE` 的订阅者。**看不到就严禁让机器人动。首次部署必须专人守急停。**

## 排障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| client 报 `Policy server did not return an RTC chunk id` | 服务端没开 RTC 但客户端加了 `--rtc` | 去掉 `--rtc` |
| 第一个动作就报错 | 底盘参数两端不一致 | 检查 server 配置名和 client `--enable-chassis` |
| server 启动报找不到归一化统计 | 忘了建 assets 软链接 | 执行 ③ |
| client 报找不到 `main.py` | `OPENPI_DIR` 没设或用了相对路径 | `export OPENPI_DIR=$(pwd)/client/openpi` |
| `run_client.sh start` 失败 | 宿主机 zenoh 服务还在跑 / 7447 被占 | 停服务、查端口 |
| 没画面 | 机器人推流目标不是 B70 的 8890 | 改推流 APP 的设置 |
| 机器人不执行指令 | 没切 API 模式 | 执行 ⑤ 第 1 条 |
| 动作延迟高 | 没绑核（仅 Guided RTC 需要） | `--cpuset-cpus=3,27` |

## 时间预估

| 步骤 | 耗时 |
|---|---|
| ① 传 42 GB（跨网中转） | 30–120 分钟，**取决于带宽** |
| ② 转 PyTorch（CPU） | 10–20 分钟 |
| ③ 软链接 | 1 分钟 |
| ④ 起 server（冷编译） | 2–3 分钟 |
| ⑤ 机器人设置 | 10 分钟 |
| ⑥ 起 client + 联调 | 15–30 分钟 |

**总计约 1.5–3 小时**，其中传输占大头。

> ⚠️ 传输是最大工程风险。**建议现在就开始测 B70 → A100 的直连速度**，不要等到 checkpoint 出来才发现传不动。
