## 六、已知的坑（都已踩过，别再踩）

1. **`FileExistsError`**：LeRobot 数据集目录已存在会直接报错，重跑必须换 `--output` 名或先删目录
2. **分辨率不可改**：写进 `meta/info.json` 后固定，换参数必须新目录
3. **`--verbose` 才有终端输出**：默认日志写到 `scripts/logs/`，不加会以为"卡死"
4. **`docker run -it` + 管道 `| tee`** 会卡住，改用 `-i`
5. **不带 `--user 0:0`** 会 `PermissionError`（镜像默认用户不是 root）
6. **保存间隔不要大于总步数**，否则可能一个 checkpoint 都不存
7. **预热步数要按总步数调**，5000 步预热对 2125 步的训练等于全程爬坡
8. **exFAT 盘上的 SSH 私钥**无法通过权限检查，必须放 NTFS
9. **B70 的 `openpi-xpu-env` 没有 VA 驱动**，VA-API 只在 `rosbag2lerobot` 镜像里可用

## 七、训练 v1 失败记录（2026-11-14 18:00）

### 现象

`v1-25e` 训练跑完 2125 步，但 **loss 爆炸到百万级**：

```
step     0  loss 16.801        grad_norm 47.7
step    10  loss 275,680       grad_norm 280
step    20  loss 948,773       grad_norm 593
step   200  loss 3,503,598     grad_norm 1,325
step  1200  loss 2,539,365     grad_norm 453,347
step  2120  loss 1,307,036     grad_norm 8,983,703
```

对比：冒烟训练（sample 数据集、同配置）loss = **0.019**。

**结论：模型完全不可用，不要部署。**

### 根因

19 维动作 = 左臂 7 + 左夹爪 1 + 右臂 7 + 右夹爪 1 + **底盘 3**。
采集时为桌面抓取，**机器人全程没开车**，底盘速度恒为 0。

归一化统计对比（`move_vaapi` vs 可用的 `teleavatar_v2_move_sample`）：

| 维度 | 好数据 std | 坏数据 std |
|---|---|---|
| dim 16（底盘 vx） | 0.0296 | **0.00089** |
| dim 17（底盘 vy） | 0.0822 | **0.00351** |
| dim 18（底盘 wz） | 0.2060 | **0.0** |

且底盘维度的 `q01` 与 `q99` 都是 `-0.00001`，几乎相等。

**归一化公式 `(x - q01) / (q99 - q01)` 分母 ≈ 0 → 数值放大到百万级 → loss 爆炸。**

失败发生在**第 10 步**，说明不是训练发散，而是**数据侧的归一化问题**。

### 修复方案

改用 **`pi05_teleavatar_v2`（16 维，不含底盘）** 重新训练：

| 项 | 原（坏） | 改为 |
|---|---|---|
| 训练配置 | `pi05_teleavatar_v2_chassis` | **`pi05_teleavatar_v2`** |
| 动作维度 | 19 维（含底盘） | **16 维（纯手臂）** |
| 底盘控制 | 模型（数据里没有） | **代码** |

这与既定架构一致——底盘本来就由代码控制，模型只管手臂。

### 部署侧连带修改（三处，缺一不可）

| 项 | chassis 版 | 16 维版 |
|---|---|---|
| server `--policy.config` | `pi05_teleavatar_v2_chassis` | **`pi05_teleavatar_v2`** |
| client 参数 | 加 `--enable-chassis` | **不加** |
| assets 软链名 | `checkout_224_plus_no_scan_224` | **`path-to-dataset`** |

### 经验

- **训练第一步必须看 loss 曲线**，不要等跑完才评估。loss 在第 10 步就异常，1.2 小时白跑。
- **常量的动作维度会炸归一化**。凡是指定配置里有、但数据里没变的维度，都会触发同类问题。
- 以后要训带底盘的模型，录制时必须真的用摇杆开车。

## 八、官方训练规范（2026-11-14 22:00 官方通知）

> 开始训练前请注意 WebUI 上显示的总步数。推荐保持默认批大小 64，调整轮数使**总步数在 5000–10000 之间**。如数据较少、15 轮仍达不到 3000 步，请降低 batch size 以达到 3000 步。

**换算公式：**

```
每轮步数 = 总帧数 ÷ batch_size
总步数   = 轮数 × 每轮步数
```

**这直接解释了 v2 为什么表现差**：v2 只有 2,125 步，低于 3,000 兜底下限。
