## 第 4 步：★ 手臂动作自检（终端 3）★

**这是最重要的一步。不启动模型，直接验证"手臂能不能被指令驱动"。**

```bash
cd /root/USB/deploy

client/run_client.sh exec bash -c '
# 心跳（和本次测试同生共死）
ros2 topic pub -r 20 /api/fsm/enable std_msgs/msg/Float32 "{data: 1.0}" >/dev/null 2>&1 &
HB=$!
sleep 1

echo "--- FSM 状态（必须是 1）"
timeout 2 ros2 topic echo --once /fsm_state --field data

b=$(timeout 2 ros2 topic echo --once /left_arm/joint_states --field position 2>/dev/null | grep -o "array.*")
echo "BEFORE: $b"

# 发一个明显不同的目标
ros2 topic pub -r 20 /api/left_arm/joint_cmd sensor_msgs/msg/JointState \
  "{position: [0.70, 1.60, -0.90, 1.10, 0.50, -0.40, 0.60]}" >/dev/null 2>&1 &
PUB=$!
sleep 5
kill $PUB 2>/dev/null

a=$(timeout 2 ros2 topic echo --once /left_arm/joint_states --field position 2>/dev/null | grep -o "array.*")
echo "AFTER : $a"

kill $HB 2>/dev/null
'
```

### 判断

| BEFORE vs AFTER | 结论 | 下一步 |
|---|---|---|
| **数字明显变化** | ✅ 手臂能驱动 | 进第 5 步 |
| **数字几乎相同** | ❌ 执行链路有问题 | 见下方排查表 |

⚠️ 跑之前**手放急停**。手臂会转约 0.4 弧度（23°）。

### 如果不动的排查顺序

1. `/fsm_state` 是不是 1？（不是 → 心跳没生效）
2. 机器人急停是不是旋开的？
3. 机器人是不是 API 模式（`current_mode=1`）？
4. **关掉碰撞检测**再试（System Config → 碰撞检测 → 关 → Save → Apply）
5. 物理推一下手臂：**有力（掰不动）= 已上电；软 = 未上电**（未上电就得找现场）

## 第 5 步：跑模型（终端 4）

**只有第 4 步通过后才做。**

```bash
cd /root/USB/deploy

client/run_client.sh exec bash -c '
# ① 心跳（与 main.py 同生共死）
ros2 topic pub -r 20 /api/fsm/enable std_msgs/msg/Float32 "{data: 1.0}" >/dev/null 2>&1 &
HB=$!
sleep 1

# ② 复位
echo "========== 复位 =========="
python examples/teleavatar_v2/zero.py

# ③ 跑策略
echo "========== 策略 =========="
sleep 1
python examples/teleavatar_v2/main.py \
  --remote-host 127.0.0.1 --remote-port 8000 \
  --video-decode va --prompt "pick sandbag"

# ④ 清理
kill $HB 2>/dev/null
'
```

### 参数说明

| 参数 | 值 | 不能错的地方 |
|---|---|---|
| `--prompt` | `pick sandbag` | 必须和训练 `--task` 一字不差 |
| `--video-decode` | `va` | 硬解，用 renderD129 |
| `--enable-chassis` | **不加** | 16 维模型含底盘会报错 |
| `--rtc` | **不加** | 服务端没开 RTC |

### 已知问题：`Observation unavailable — dead sensors`

如果出现：

```
ERROR: Observation unavailable — dead sensors:
  video:head_left_eye: 1.2s stale ...
Stopped decoder after 51 frames
```

**含义**：3.5 秒只解码 51 帧（约 15 fps），远低于 45 fps，部分画面 1.2 秒没更新，安全机制主动停止。

**排查**：
```bash
# 机器人推流速率（10 秒应有数千包）
sudo timeout 10 tcpdump -i any -n udp port 8890 2>/dev/null | wc -l

# GPU 利用率（跑 main.py 时）
watch -n 1 'xpu-smi dump -d -1 -m 0,18 -n 1'
```

| 现象 | 含义 |
|---|---|
| GPU 0（server）< 10% | 推理没发生 |
| GPU 0 > 30% | 推理正常，瓶颈在解码 |
| GPU 1（解码）< 10% | 解码没跑起来 |

**临时缓解**：报错后立刻再跑一次（`torch.compile` 缓存已建立）。

## 安全停止

```bash
# 正常：Ctrl-C
# 或
client/run_client.sh exec pkill -INT -f examples/teleavatar_v2/main.py
# 或
client/run_client.sh stop
```

**严禁 `docker stop` / `kill -9` / `rm -f`** —— 跳过零速度指令，底盘会继续动约 1 秒。

**SSH 断连不会停止程序**，机器人会继续运动。断网先拍急停。

## 一页速查

```
终端1：server（监听 8000）
终端2：client 容器（RENDER=renderD129）
终端3：自检 + 手臂动作测试
终端4：跑模型（心跳 + zero.py + main.py）
```

**核心三句话：**
1. **心跳必须和程序同 shell**，否则 1 秒后手臂自动暂停
2. **先自检手臂能动，再跑模型**——否则会误判成模型问题
3. **`--prompt` 必须和训练时完全一致**
